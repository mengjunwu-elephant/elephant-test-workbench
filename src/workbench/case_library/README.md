# 本项目用例资产

此目录随本项目源码 Git 提交，应用运行时仅访问本项目文件，不依赖旧工程存在。

- `cases/<机型>/*.json`：用例定义、原始参数组、来源行号、转换状态与前置/验证/恢复步骤。
- `sources/**/*.txt`：经授权从 elephant-pytest 一次性迁入的测试、fixture 和公共方法逻辑依据，仅查看，绝不导入或执行。设备初始化、连接地址和环境密钥配置不作为运行依赖迁移。
- `migration-manifest.json`：来源哈希、空表、文件覆盖范围及转换限制。
- `remediation-ledger.json`：全部原条目及未绑定来源的逐函数整改台账、承接场景、阻断原因与实机验收状态。
- `plans/*.json`：显式写回的测试计划，包含有序条目和固定版本的用例定义快照；初始目录可以为空。

2026-11-13 基线：9 个工作簿、457 张工作表、3,232 组参数；456 份非空原始用例，14 份只读场景已转为读取/断言步骤，442 份复杂场景纳入整改；1 张空表记录在清单。源测试文件 514 个、测试函数 835 个；这些数量的含义不同，不当作可执行用例数量。

0.5.0 首批整改：其中 25 个原始聚合条目已完整拆分承接为 77 个 Pro450 场景，保留原条目及映射；其余 417 个原条目仍有阻断，46 份未绑定来源单独记录。当前共 533 份定义，仅原 14 份保持启用；新增 77 份默认禁用，转换完成与实机验收分开记录，不能视为设备测试通过。

原 Excel 字符串保持原样，不执行 eval。包含防碰撞条件、运动、人工输入、双臂、特殊异常或 fixture 恢复依赖的场景，不得删掉关键逻辑后冒充迁移完成。单例步骤在用例库内编辑、核对后启用；编排页只组合已有定义，后端同时阻断未启用/待完善用例。

使用流程：保存草稿 → 写回文件 → 审查差异 → Git 提交 → 推送。另一工作区拉取后载入文件。设备连接、SDK、数据库、日志、结果不写入此目录。冲突需要人工处理，不自动覆盖；源码拉取接受整个工作区干净的快进更新。

迁移脚本位于项目 scripts/，只接受明确指定的来源，并拒绝覆盖已有资产。整改脚本 `scripts/remediate_case_library.py` 只静态解析已迁入本项目的文本，按来源生成可复现的场景和台账；不导入旧模块，不连接设备，也不能证明 SDK/固件或实机兼容性。
